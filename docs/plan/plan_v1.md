# JSON 本地工作区方案 v1

- 日期：2026-11-22
- 状态：v1 已在本地实现，实施记录与验证范围见第 10 节。
- 范围：仅 JSON 格式化页面；保持现有工具导航和深浅主题。

## 1. 目标与现状

当前 `JsonFormatter.tsx` 的输入、输出、JSONPath 和压缩开关均为组件内存状态，切换工具或刷新后不能恢复。页面已有查询栏、左右 Monaco 编辑区，滚动刚统一为查询栏固定、编辑区内部滚动。

本次将它扩展为浏览器本地 JSON 工作区：左侧树管理文件夹和 JSON 文档，选中文档后在右侧编辑、格式化和查询。正文与目录不请求 Worker、不写入 R2；不同浏览器、浏览器用户配置及站点 origin 的数据互不共享。

文件夹可以为空；节点类型由 `kind` 判定，不能把“没有子节点”直接当成 JSON 文件。

## 2. 推荐布局

```text
应用导航（保持现状）
┌──────────────────┬──────────────────────────────────────────┐
│ 本地 JSON         │ JSONPath 输入框                  执行查询 │
│ ＋文件 ＋文件夹 ⋯ │ 当前文件路径 / 保存状态                  │
│ 搜索名称          ├────────────────────┬─────────────────────┤
│ ▾ demojson       │ 输入 JSON   格式化 │ 结果 压缩 字符数 复制 │
│   ▾ JP           │                    │                     │
│     plp.json     │ Monaco 输入        │ Monaco 只读结果     │
│   ▾ KR           │                    │                     │
│     reco.json    │                    │                     │
└──────────────────┴────────────────────┴─────────────────────┘
```

- 树是独立侧栏，不叠加在输入编辑器内部；建议初始宽 240px，可折叠，v1 暂不做拖动调宽。
- 目录栏与当前文档栏使用真实 DOM，不放入 Monaco 滚动内容。
- 桌面：工作区占剩余视口，树与两个编辑器分别滚动；查询栏、工具栏不随正文滚动。
- 中等宽度：可折叠树，保留左右编辑区；可用编辑区域过窄时切为上下排列。
- 手机：树以抽屉打开，选中文档后关闭；正文沿用上下两面板、面板区域滚动，查询栏保持可见。
- 所有 flex/grid 收缩链设置 `min-height: 0` 和 `min-width: 0`；不用内容行数决定整个工作区高度。Monaco 允许边界滚轮向面板滚动区传递。
- 同时适配应用顶部导航、应用左侧导航以及深浅主题。抽屉关闭后恢复触发按钮焦点。

## 3. v1 功能范围

### 3.1 文件树

- 新建文件夹、新建 JSON、重命名、删除、移动到指定文件夹。
- 点文件夹箭头展开或收起；点 JSON 打开文档，不因点文件夹而关闭当前文档。
- 新建位置：选中文件夹内、选中文件所在文件夹内，未选择时在根目录。
- 新 JSON 默认名 `未命名.json`，同级重名自动递增；内容建议 `{}`，创建后进入重命名并聚焦编辑器。
- 同级名称不重复，文件夹与文件共用同级名称空间；去除首尾空白，禁止空名称、斜杠和控制字符，建议上限 100 字符。
- JSON 后缀在重命名时统一补齐，名称不作为主键；改名和移动不改变文档 ID。
- 文件夹排前，名称排序；v1 不支持手动排序和拖拽，使用“移动到”菜单降低误操作。
- 文件夹不能移入自身或后代，目的节点必须为仍然存在的文件夹；结构验证与写入在同一事务内完成。
- 删除前确认名称及包含的文件数量；递归删除原子执行。v1 无回收站，提示先备份。
- 搜索仅匹配名称，显示命中项及祖先路径；清空搜索后恢复原展开状态，不做正文全文搜索。
- 菜单按钮和键盘均可操作：方向键导航/展开、Enter 打开、F2 重命名；编辑器输入期间不拦截这些快捷键。

### 3.2 文档与结果

- 同时只编辑一个文档，v1 不引入多标签页 UI。
- 原始输入字符串是权威正文，保留缩进、换行以及尚未完成或无效的 JSON。自动保存不以 JSON 校验成功为前提。
- 格式化、JSONPath 只更新结果，不自动覆盖源正文。
- 查询表达式按文档保存；压缩开关作为工作区偏好保存。
- 结果为派生数据，不存入 IndexedDB。重新打开时，对合法正文生成普通格式化结果；不自动执行上次 JSONPath 查询，避免把查询结果误认为完整文档。
- 输入改变后，旧结果清空或明确标记“输入已变更，请重新执行”；推荐清空，避免复制旧数据。压缩切换仅重排当前有效结果。
- 切换文档时，先保存当前草稿再读取目标，清理旧结果和错误。异步加载绑定文档 ID 与请求序号，快速连续点击时仅最新选择可更新视图。
- 编辑器使用文档 ID 作为 Monaco model 标识；保留当前会话的光标与滚动位置。关闭/删除时释放不用的 model，不能为整个文件树预建全部 model。
- 当前递归解析“字符串内 JSON”的行为可能改变数据类型；建议后续改为独立显式操作，普通格式化只做语法解析和缩进。该行为是否纳入 v1 待讨论。

### 3.3 初次进入与删除后行为

- 空库显示创建 JSON / 导入文件入口，不自动制造示例目录。
- 恢复上次选中文档；不存在则选第一个可用文档，没有文件则展示空态。
- 删除当前文档或其祖先后清空编辑区，选择同级下一项；无下一项则回到空态。
- 点击另一个工具前提交当前草稿；失败时保留草稿并提示，不静默卸载丢失数据。

## 4. 本地存储设计

推荐 **IndexedDB 保存目录与正文，localStorage 仅保存 UI 偏好**。正文不使用 localStorage，以避免同步大字符串读写阻塞输入，也避免两份正文互相覆盖。

建议数据库名 `react-tools-json-workspace`，初始版本 1。不与已有 R2 配置或笔记存储混用。

| Object store | 主键 | 字段 | 索引 |
| --- | --- | --- | --- |
| nodes | id | kind、parentId、name、createdAt、updatedAt | parentId；parentId + name 唯一索引 |
| documents | nodeId | text、jsonPath、revision、updatedAt | 暂无 |

- `kind` 为 `folder` 或 `json`；根目录为虚拟节点，父 ID 使用固定字符串 `root`，避免 null 不进入索引导致根节点唯一约束失效。
- ID 使用 `crypto.randomUUID()`；时间戳为毫秒数。
- JSON 节点与正文必须同事务创建/删除；文件夹无正文记录。树只读取元数据，打开文档再读取正文。
- `revision` 初始为 1，每次正文或查询表达式成功写入递增；用于跨标签页并发检查。
- UI 偏好建议集中为 `STORAGE_KEYS.jsonWorkspacePreferences`：selectedId、expandedIds、sidebarCollapsed、isMinified。读取校验类型、过滤已删除 ID；localStorage 写失败不影响正文保存。
- IndexedDB schema 升级通过版本升级事务执行；升级阻塞时提示关闭其他标签页，在 `versionchange` 时关闭旧连接，不删库重建。
- 不新增全局业务状态中枢；工作区控制器管理加载/选择/保存，存储模块显式接收参数，不依赖 React。

## 5. 保存与一致性

### 5.1 自动保存

建议输入后 500ms 防抖，连续输入最多每 2 秒提交一次；切换文档、离开工具和页面隐藏时立即尝试提交。

状态明确区分：加载中、已修改、保存中、已保存到本机、保存失败、存在冲突。只有 IndexedDB 事务完成后显示“已保存”，不以发起请求作为成功。

每份草稿携带文档 ID、编辑序号和基线 revision。串行提交同一文档，保存成功仅确认对应编辑序号；保存期间的新输入仍保持脏状态并继续提交，禁止旧回调把较新输入标成已保存。

切换流程：冻结切换目标 → flush 当前草稿 → 成功后加载目标。保存失败留在当前文档，允许重试或导出草稿。快速选择采用最后一次目标，避免多份并发加载。

关闭页面的异步提交不能保证完成；以持续自动保存降低风险，脏状态注册 `beforeunload` 提醒，不宣称关闭瞬间零丢失。组件卸载只作为最后补救，应用工具切换需先经过可等待的保存流程。

### 5.2 多标签页

- 写入事务读取数据库 revision 并比较基线；相同才更新，冲突则拒绝覆盖。
- `BroadcastChannel` 只广播节点 ID / revision / 操作类型，不广播正文，通知其他页面刷新元数据。
- 未修改的当前文档可重新读取；存在本地修改时保留草稿，提供“加载本地库版本”或“另存为副本”，不自动合并 JSON。
- 删除不允许被晚到的保存任务复活：保存只更新仍存在的节点；收到外部删除通知后，未保存内容允许另存副本。
- BroadcastChannel 是通知手段，事务 revision 检查才是正确性保障。

### 5.3 异常与容量

- IndexedDB 不可用时明确显示“临时编辑，刷新会丢失”，可复制/下载，不伪装为已持久保存，也不偷偷回退到 localStorage 存正文。
- 配额不足、事务失败时保留内存草稿，提示重试与导出；不自动清理用户文件。
- 本地存储不是备份，清除站点数据、换域名或换浏览器不会自动迁移；产品内提供简短说明及导出入口。
- v1 建议单文档上限 5 MiB（UTF-8）、节点数上限 2,000、嵌套层级 20；这些是待验证的产品限制，不是浏览器配额承诺。达到限制时保留已有内容并给出明确反馈。

## 6. 导入与备份

建议 v1 包含：导入多个 `.json` 文件、下载当前文档、整库导出与导入备份。

- 文件导入到当前文件夹；文件名冲突自动重命名。允许无效 JSON 作为待修复草稿，但标记解析错误。
- 整库备份包含格式标识、schemaVersion、导出时间、nodes、documents，不含令牌和其他工具数据。
- 导入先校验大小、版本、引用关系、重复 ID、循环目录、节点类型和正文配对，再一次事务写入。
- v1 推荐仅支持“作为新文件夹合并导入”，为导入节点重新分配 ID，不提供覆盖整库操作。
- 未完成保存的当前草稿需先 flush；失败则提供单独下载草稿，不能把旧库快照称为最新备份。

## 8. 实施顺序与验收

1. 实现数据模型与事务测试：CRUD、移动循环、递归删除、revision 冲突、升级阻塞。
2. 实现树与空态，再接入已有编辑区；先验证桌面/窄屏/侧栏滚动。
3. 接入自动保存、文档切换、加载竞态、离开工具保护与多标签页通知。
4. 实现导入导出、异常状态、主题和键盘交互。
5. 类型检查、生产构建、单元测试及浏览器回归。

验收重点：

- 新建文件夹和 JSON → 编辑 → 切换 → 刷新，树和原始正文一致恢复，包括无效 JSON。
- 持续输入、快速切换、保存中继续输入，不串文档、不漏最后一次确认过的编辑。
- 移动后引用仍正确；删除父目录清理全部后代，待提交任务不能复活文档。
- 两个标签页同时修改同一文档，能发现冲突且不静默覆盖。
- 保存失败时不显示“已保存”，可导出当前草稿。
- 格式化、JSONPath、压缩、复制在切换文件后不展示或复制上个文件结果。
- 长文件、空文件、错误提示、折叠侧栏、窗口缩放、触屏滚动均不遮挡查询栏与操作按钮。
- 浅色/深色、键盘树导航、菜单焦点、编辑器快捷键互不干扰。
- 备份导出后导入新目录，节点层级和正文可逐项核对；异常备份不会半途写入。

## 9. 本轮讨论建议

以下为推荐默认值，均可调整：

1. **文件夹 + JSON 的本地工作区**，首期不接云同步、不做多工作区。
2. **自动保存原始草稿**，即使 JSON 无效也保存；只持久化输入，不持久化输出。
3. **侧栏 240px、可折叠**，手机用抽屉；不让文件树占用输入编辑器内容区域。
4. **移动菜单优先**，拖拽排序、回收站、版本历史、多编辑标签留到后续。
5. **备份纳入 v1**，避免本地目录成为无法迁出的数据孤岛。
6. 是否把现有“递归解析 JSON 字符串”改成显式选项，以及单文件大小上限，需要优先确认。

## 11. 单编辑器交互调整（2026-11-22）

按后续需求，原左右输入/结果面板合并为一个全宽编辑器，取代第 2、3 节的双面板描述：

- 工具栏合并格式化、压缩、字符数和复制；格式化直接将当前文档排版为两空格缩进，压缩切换立即更新文档，并由原自动保存机制落盘。
- 文档替换通过 Monaco 编辑操作执行，保留撤销/重做历史；无效 JSON 不修改正文或压缩偏好。
- JSONPath 在同一编辑器显示只读查询预览，提供“返回文档”；预览使用独立 model，不覆盖持久化正文。预览内格式化、压缩和复制仅作用于查询结果。
- 查询结果不会落盘；切换文档或刷新后恢复原文。model 切换时校验实际 model URI，避免旧 onChange 回调将查询结果保存为正文。
- 桌面和手机均使用填满剩余高度的单编辑区，不再使用上下两个固定高度面板。

## 12. 编辑区精简（2026-11-22）

按后续界面要求，移除顶部文件路径/保存状态/下载栏和 JSONPath 查询栏，取消查询预览交互。保留后台自动保存，失败时仍显示错误及下载草稿等恢复操作。文件树开关并入编辑器标题栏，标题栏压缩为约 40px，保留格式化、压缩、字符数和复制。已有文档中的 jsonPath 字段暂保留，不影响原始正文。

## 13. JSON 结构面包屑（2026-11-22）

- 在紧凑工具栏下新增固定 26px 的结构导航，显示文件名、光标所在对象属性及数组下标。
- 点击路径节点打开可展开结构树，展示类型图标和值摘要；点击节点跳转并选中源码，展开目标的折叠祖先。支持方向键、Enter、空格、Esc 和点击外部关闭。
- 使用 Microsoft `jsonc-parser` 进行容错结构解析，保留 UTF-16 源码位置。解析在本地打包的专用 Web Worker 中运行，正文变化防抖 180ms，光标变化仅在既有结构上查找。
