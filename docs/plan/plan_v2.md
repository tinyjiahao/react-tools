# Tool Suit 命名与 JSON 工作区界面调整方案（V2）

- 日期：2026-11-24
- 状态：已实现并完成本地验证
- 本次交付：功能代码、回归测试及本地开发环境；已部署 Cloudflare Workers，代码随本次发布提交。

## 1. 目标与范围

将网站标题改为 **Tool Suit**，将 JSON 文件树顶部的 **本地 JSON** 改为 **JSON工具**。名称严格采用用户指定的 `Tool Suit`，不改写为 `Tool Suite`。

新增明确需求：JSON 工具页面支持拖动左侧文件树与右侧编辑区之间的竖向分隔条，实时调整左右区域宽度。此交互纳入 V2 实施范围。另在 JSON 编辑器右上角工具栏新增“属性”按钮，以右侧抽屉管理当前 JSON 文件的自定义附加信息，支持任意添加和编辑 key/value。

另外，文件树节点“⋯”操作改为弹出菜单，禁止在节点行内展开操作列表并撑大行高。

## 3. 命名方案

2. 将文件树标题 `本地 JSON` 设置为 `JSON工具`。
3. 浏览器标题在各工具页面保持 `Tool Suit`，本轮不增加文件名或工具名后缀，也不引入动态 document.title 逻辑。
4. 已有导航分类 `JSON工具` 保持原样，编辑区标题 `JSON 编辑器` 保持原样，分别表达工具分类和编辑区域。

### 3.2 已统一的品牌展示

标签页、导航、分享卡片与安装应用已统一名称：

| 展示位置 | 已实现值 |
| --- | --- |
| 导航品牌 `.logo-text` | Tool Suit |
| Open Graph `og:title` | Tool Suit |
| manifest `name` | Tool Suit |

不更改域名、路由、仓库名、package name、Worker 名称、R2 桶名称、图标、IndexedDB 数据库名或 localStorage key。界面改名不涉及数据迁移；“保存在本机”等存储说明继续保留，避免用户误认为 JSON 已上传云端。

## 4. 左右区域拖拽调宽（已纳入范围）

### 4.1 布局与交互

- 在文件树与编辑区之间新增自定义 `JsonWorkspaceSplitter` 分隔组件，采用原生 Pointer Events，不新增依赖。
- 分隔条占用 6px 宽度，中间显示 1px 主题分隔线；悬停、键盘聚焦和拖拽时使用主题强调色，鼠标显示 `col-resize`。
- 按住分隔条左右拖动时，左侧文件树宽度实时变化，右侧编辑区填充剩余空间。空工作区与已有文档状态都支持调宽。
- 使用指针捕获，避免鼠标进入 Monaco 或离开分隔条后拖拽中断；拖拽期间临时禁用文本选择，仅在分隔条设置适当的 touch-action。
- 指针释放后提交宽度；Esc 取消拖拽并恢复开始时宽度。pointercancel、意外丢失指针捕获、组件卸载时清理交互状态，不留下光标或禁止选中文本的样式。
- 双击分隔条恢复默认宽度；现有侧栏折叠按钮保持可用，折叠时隐藏分隔条，展开时恢复上次宽度。

### 4.2 宽度限制与响应式

已实现参数（均指 CSS 像素，侧栏宽度包含 padding 与边框）：

| 参数 | 实现值 |
| --- | --- |
| 默认侧栏宽度 | 240px |
| 最小侧栏宽度 | 200px |
| 最大侧栏宽度 | 480px |
| 右侧编辑区最小保留宽度 | 360px |
| 分隔条占用宽度 | 6px |

以 JSON 工作区容器实际宽度 W 计算有效上限：`min(480, W - 360 - 6)`，不要使用整个浏览器窗口宽度代替容器宽度。实际侧栏宽度限制在最小值与有效上限之间，避免左侧全局导航挤占空间时编辑器被压没。

- 使用 ResizeObserver 监听工作区容器；窗口缩放、全局导航切换和侧栏展开时重新计算约束。
- 保留现有 700px 以下的抽屉布局；若容器不足 566px，也使用抽屉模式，避免最小宽度约束互相冲突。
- 抽屉模式隐藏分隔条并禁用拖拽，保留遮罩、Esc 关闭与焦点管理；桌面宽度偏好不被抽屉宽度覆盖。
- 视口临时变窄时只限制显示宽度，不覆盖用户保存的偏好，恢复宽屏后重新应用。

### 4.3 状态与持久化

- 在 `useJsonWorkspace.ts` 的 Preferences 中增加可选兼容读取的 `sidebarWidth`，默认 240px。
- 复用 `STORAGE_KEYS.jsonWorkspacePreferences` 保存宽度，不新增存储 key，不迁移 IndexedDB 文档。
- 读取时校验有限数值并限制在 200–480px；缺失、非数字或无效值回退默认宽度。
- 拖拽临时宽度使用组件状态或 ref 管理，通过 requestAnimationFrame 合并更新；不要每次 pointermove 都写 localStorage。
- 拖拽完成、双击重置或键盘调整完成时保存偏好；存储失败不阻断调宽，沿用安全写入逻辑。

### 4.4 编辑器布局与可访问性

- 侧栏使用动态 CSS 变量控制宽度，右侧继续保持 `flex: 1`、`min-width: 0`、`min-height: 0`，不新增页面级滚动容器。
- 确认 Monaco 的 automaticLayout 能跟随容器变化；如需补充 layout 调用，使用 ResizeObserver 与 requestAnimationFrame 合并，避免每次移动重复触发布局。
- 分隔条可通过 Tab 聚焦，使用 `role="separator"`、`aria-orientation="vertical"`，提供中文标签“调整文件树宽度”及 aria-valuemin / aria-valuemax / aria-valuenow。
- 左右方向键每次调整 10px，Home / End 调整到有效最小/最大宽度；提供可见焦点样式。
- 保留文件树与 Monaco 的独立滚动、编辑内容、撤销历史、选中文件及搜索替换面板，不因调宽重新挂载编辑器。

## 5. JSON 文件属性抽屉

### 5.1 入口与布局

- 在 JSON 编辑器自身的右上角工具栏末尾（字符统计之后）增加属性图标按钮，与搜索、复制按钮统一尺寸和间距；不是全站导航栏按钮。
- 点击打开右侧抽屉，再次点击或点击抽屉关闭按钮关闭；无选中文档时不显示可操作入口。
- 抽屉标题为“文件属性”，同时显示当前文件名，避免属性与文件关联不明确。空状态提示“暂无属性”，提供“添加属性”按钮。
- 桌面端采用编辑区内覆盖式抽屉，宽度 480px（由原 360px 加宽），最大不超过编辑区可用宽度，不改变左侧文件树的宽度，也不挤压 Monaco；可继续操作未被覆盖的编辑区。
- 窄屏采用带遮罩的模态抽屉，宽度不超过可用视口；打开前关闭左侧文件树抽屉，避免两个抽屉叠加。
- 抽屉表头为 `Key`、`Value`，每行提供两个可编辑字段和删除按钮；Value 支持多行文本。底部提供“添加属性”，新增后聚焦新行 Key。
- 抽屉头部固定，属性列表独立纵向滚动，底部操作区保持可访问。长文本不撑破抽屉；窄屏可将同一行的 Key、Value 上下排列。

### 5.2 属性入口与抽屉样式（已实现的后续优化）

- 属性面板由 360px 加宽至 480px，使用 `width: min(480px, 100%)`；Key、Value 列按原比例获得更多空间，窄屏限制在容器宽度内，保持独立滚动与遮罩关闭行为。

- 工具栏顺序为：格式化、压缩、搜索、复制、字符统计、属性。属性入口不再显示文字或描边文字按钮，使用共享 `Icon` 的 `properties` 圆圈信息“i”图标（18px），不引入图标库。
- 属性按钮点击区域为 28 × 28px，与搜索、复制入口保持一致；悬停提示“文件属性”，保留 `aria-label="属性"`、`aria-expanded` 和 `aria-controls`。展开时使用主题强调色及悬停背景显示选中状态。
- 抽屉标题字号为 14px、行高 20px，文件名为 12px 次要文字，超长省略并保留悬停全文。头部内边距为上下 12px、左右 16px，关闭按钮垂直居中，避免被拉伸成高按钮。
- 关闭、删除均使用 28 × 28px 无边框图标按钮，内部图标为 16px；关闭使用叉号，删除使用垃圾桶。悬停提供背景反馈，删除悬停使用危险色，并保留中文可访问名称。
- 属性列表内边距为 16px；每行使用 `Key : Value = 1 : 1.5` 的弹性列及 28px 删除按钮列，列间距 8px、行间距 16px。字段标签与输入框间距 6px，删除按钮对齐输入区域。
- Key 输入框和 Value 文本框初始高度统一为 34px，字号 13px、行高 18px、内边距上下 7px/左右 9px。Value 从单行高度开始，仍支持多行输入及纵向手动调高；不是随内容自动增高。
- 输入框聚焦时使用主题强调色边框。所有背景、文字和普通交互反馈复用主题变量，支持深色和浅色模式。
- 底栏内边距为上下 12px、左右 16px，操作与保存状态间隔 12px；“添加属性”保留文字并配 14px 加号图标，按钮最小高度 30px。保存状态使用 11px 次要文字，减少视觉干扰。
- 本轮仅调整展示与交互反馈，不改变属性字段规则、正文内容、保存队列或持久化格式。

### 5.3 自定义字段规则

- Key 和 Value 均由用户自由输入，不预设字段清单；以字符串原样保存，不自动转成数字、布尔值或 JSON。
- 每行使用独立稳定 ID，而不是 Key 作为 React key。允许重复 Key、空 Value 和编辑中的空 Key，避免自动保存时因未填完字段阻断输入。
- 点击“添加属性”即建立一行，空行作为草稿保留，只有明确删除时才移除。默认按添加顺序展示，本轮不增加排序、模板或字段类型选择。
- 属性属于文件附加信息，不写入 JSON 正文；格式化、压缩、复制正文、字符统计和普通 `.json` 下载仅作用于正文。
- JSON 正文无效时仍可编辑属性。所有文本按纯文本显示，不解释 HTML，不执行脚本。

### 5.4 数据模型与保存

建议在现有 WorkspaceDocument 记录中增加属性数组，按稳定的 nodeId 关联文件：

```ts
interface JsonFileProperty {
  id: string;
  key: string;
  value: string;
}

// WorkspaceDocument 新增字段；旧记录读取时补空数组。
// properties: JsonFileProperty[]
```

- 属性随正文保存在浏览器 IndexedDB，不调用 R2 API；文件重命名、移动时关联不变，删除文件或父文件夹时随文档一起删除。
- 沿用现有 documents object store，新增记录字段不需要改变数据库版本；读取旧记录时规范化为 `properties: []`，新文档默认空数组。
- 扩展现有 useJsonWorkspace 的编辑入口和保存队列，使正文与属性修改合并到同一份最新文档快照，统一使用 revision 检查，防止相互覆盖。
- 属性输入采用与正文一致的防抖自动保存，抽屉显示“保存中 / 已保存 / 保存失败”状态。关闭时触发 flush，失败保留内存草稿并显示可重试提示，不误报已保存。
- 切换文件前等待当前修改保存成功，再加载目标文件属性；保存失败或发生冲突时保持当前文件，避免将旧属性写入新文件。
- 桌面端切换文件后，已打开抽屉跟随新文件更新；当前文件被删除或切换到其他工具时关闭抽屉。抽屉打开状态不持久化。
- 复用跨标签页冲突检测，冲突时不能静默覆盖。冲突副本、恢复草稿需包含正文和属性；另提供包含二者的恢复下载，区别于纯 `.json` 正文下载。
- 临时编辑模式允许填写属性，但明确提示刷新可能丢失，并支持下载恢复数据。
- 扩展存储校验，验证属性数组、行 ID 唯一性及 key/value 字符串类型。建议正文与属性序列化后的合计大小上限为 5 MiB，超限保留草稿并提示，禁止静默截断。
- 扩展现有工作区备份函数以包含属性：导出 schemaVersion 2，导入兼容版本 1（属性补空数组）与版本 2，拒绝未知版本。无需恢复此前移除的备份按钮，本轮只保证数据层完整性。

### 5.5 可访问性与交互协调

- 属性按钮提供 aria-expanded、aria-controls；抽屉使用有标题的 dialog，窄屏模态模式设置 aria-modal，桌面非模态不限制整个页面焦点。
- 打开时聚焦抽屉内首个可操作元素，关闭后回到“属性”按钮；每行删除按钮具有可识别的中文名称。
- 抽屉内按 Esc 关闭抽屉并阻止事件继续传播，避免同时关闭 Monaco 搜索面板；焦点在 Monaco 时保留其 Esc 行为。
- 窄屏模态状态限制焦点在抽屉内、点击遮罩可关闭；关闭后的焦点恢复与左侧文件树抽屉规则一致。
- 不因属性增删、保存或开关抽屉重新挂载 Monaco，保留编辑器内容、光标、滚动位置和撤销历史。

## 6. 文件树节点操作改为弹出菜单

### 6.1 问题与目标

改造前 `JsonFileTree.tsx` 使用行内 `<details><summary>⋯</summary>…</details>` 展示操作，展开内容会参与节点行布局，导致选中背景和行高被撑大。

将“⋯”改为普通菜单触发按钮，操作以独立浮层显示；文件、文件夹均适用。菜单开关不得改变节点行高、文件名位置、相邻节点位置或文件夹展开状态。

### 6.2 菜单行为

- 点击“⋯”显示“重命名”“移动到”“删除”，保持现有操作含义与删除确认流程；再次点击同一按钮关闭。
- 菜单锚定触发按钮，优先向下弹出并右对齐；底部空间不足时向上弹出，横向位置限制在视口范围内，保留 8px 边距。
- 同一时间只显示一个节点菜单，点击另一节点的“⋯”时替换当前菜单。
- 触发菜单及点击菜单项不冒泡到节点选择或文件夹展开事件；操作始终绑定触发节点的稳定 ID，不依赖当前选中文档。
- 点击菜单外部、按 Esc 或执行操作后关闭。文件树滚动、侧栏折叠、拖拽调宽、窗口尺寸变化、搜索过滤或目标节点被移除时关闭菜单，避免浮层脱离目标。
- 关闭菜单不应吞掉正常的外部点击，例如点击其他文件仍能切换文件。
- “删除”使用危险操作颜色，仍需现有确认弹窗；选中菜单项后先关闭菜单，再打开对应操作弹窗。

### 6.3 实现与可访问性

- 新增自定义 `JsonNodeActionMenu`，用 React createPortal 将菜单渲染到 document.body，以 fixed 定位，避免被文件树滚动容器裁切。
- 根据触发按钮的 getBoundingClientRect 与菜单实际尺寸定位；层级高于文件树和普通编辑内容，低于模态抽屉及操作确认弹窗。
- 复用现有主题变量、圆角、边框和阴影，不新增组件库。删除 `<details>` 布局及其专用样式，保持“⋯”按钮尺寸固定。
- 触发按钮提供包含文件名的 aria-label、aria-haspopup="menu"、aria-expanded 与 aria-controls；菜单使用 role="menu"，菜单项使用 role="menuitem"。
- Enter / Space 打开后聚焦第一项；上下方向键切换菜单项，Home / End 到首尾，Enter / Space 执行。
- Esc 关闭并将焦点返回触发按钮，阻止继续触发父层抽屉的 Esc 关闭；Tab 关闭并按正常焦点顺序离开，不困住焦点。
- 打开操作弹窗时由弹窗接管焦点；因外部点击关闭时不强制抢回焦点。触发节点已删除时，回退到下一个可用树节点或文件树入口。
- 窄屏文件树抽屉的焦点管理需将 portal 菜单视为抽屉内交互区域，避免 Tab 循环和外部点击检测误关菜单。
