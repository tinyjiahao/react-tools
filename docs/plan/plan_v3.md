# JSON 字符串内嵌数据编辑方案（V3）

- 日期：2026-11-26
- 状态：已实现并发布 Cloudflare Workers；代码随本次发布提交远程。
- 适用页面：JSON工具（`/json`）。延续 V2 单编辑器、文件树、本地持久化与属性面板设计。

## 1. 实际问题

仓库 `data/demo1.json` 内容如下：

```json
{
  "a": "123",
  "content": "{\"a\":\"b\"}"
}
```

外层 `content` 的类型是字符串，其解码后的文本 `{"a":"b"}` 又是一份 JSON。现有格式化基于 `JSON.parse` / `JSON.stringify`，只处理外层，所以字符串内的转义引号仍会显示。用户需要手动复制、解码、编辑、重新转义和粘贴，容易破坏引号、反斜杠和换行。

目标：支持发现、查看、编辑并安全回写这种内嵌 JSON，同时默认保持外层字段的字符串类型。适用任意字段名、数组元素及多层嵌套，不仅限于 `content`。

## 2. 推荐交互：进入内层编辑

继续使用一个主要 Monaco 编辑区域，通过“原文 / 内嵌 JSON”编辑上下文切换，不新增常驻左右双编辑器，也不占用文件属性抽屉。

### 2.1 入口与发现

- 工具栏增加“内嵌 JSON”图标入口，带中文悬停提示和可访问名称。
- 光标位于可解析的字符串值或其对应属性名时，点击入口直接打开该字符串；光标不在候选项时，弹出当前层候选列表。
- Monaco 右键菜单增加“编辑内嵌 JSON”，与工具栏共用处理逻辑。
- 候选列表显示字段路径、对象/数组类型和简短预览，支持按路径筛选。多个候选项由用户明确选择，不默认修改第一个 `content`。
- 首版不增加每行 CodeLens，避免大量字段增加行高及扫描开销。普通字符串不显示为候选。
- 无候选时提示“当前层没有可展开的 JSON 字符串”。可提供“尝试解析当前字符串”入口，对格式错误给出原因，但绝不自动修复或替换。

### 2.2 编辑与回写流程

1. 在示例中选择 `content`，进入后展示可读的内层 JSON：
   ```json
   {
     "a": "b"
   }
   ```
2. 编辑器上方增加紧凑的上下文栏：`demo1.json > content（字符串内 JSON）`，同时提供“返回上层”“应用到上层”。上下文栏与现有光标结构面包屑区分：前者表示编辑层级，后者表示当前层光标位置。
3. 内层可使用格式化、压缩、搜索替换、复制和结构面包屑；字符统计仅统计当前层文本。工具栏文案提示复制的是“当前层 JSON”，不是带外层引号的转义字符串。
4. 点击“应用到上层”：校验当前层 JSON，按 JSON 字符串规则编码后替换父层目标字符串 token，返回父层并选中更新的字段。
5. 外层 JSON 字段类型仍为 string。例如把内层 `a` 改为 `c` 后，结果中仍是 `"content": "{\"a\":\"c\"}"`。
6. 内层编辑时以格式化文本展示；应用到上层时自动去除字符串值之外的排版空白，再转义回写，避免多层编码累积换行与缩进。字符串值本身的空格、换行和转义保持不变。不隐式把内层字符串转为对象。

仅打开、查看再返回不修改正文。首次可读展示产生的缩进视为展示初始化，不标为用户修改；用户执行格式化、压缩或输入才标记为已修改。

### 2.3 返回、文件切换与多层处理

- 未修改时直接返回；有修改时显示“应用并返回 / 放弃修改 / 继续编辑”。应用校验失败则留在当前层并定位错误。
- 内层再次包含 JSON 字符串时，支持逐层进入；每次只解码一层，不自动递归转换所有字符串。最大编辑层级暂定 8 层，超过时提示。
- 向上应用只更新直接父层草稿；最外层应用才修改文件正文并进入现有自动保存队列。界面明确显示“内层草稿尚未应用到文件”，避免将父文件的“已保存”误认为内层已落盘。
- 有未应用草稿时切换文件、离开 JSON 工具、加载冲突版本或删除当前文件，均先处理草稿。一次离开涉及多层时，提供逐层应用至原文、放弃全部或取消；中间任一层无效则停止并保留草稿。
- 文件属性仍绑定根文档 nodeId，进入内层不会创建新文件或更换属性归属。

## 3. 数据识别与准确性

### 3.1 解析规则

- 使用项目已有 `jsonc-parser` 获取严格 JSON 语法树和字符串 token 的偏移、长度及解码值，禁止通过正则寻找字段或全局替换 `\\"`、`\\n`。
- 自动候选限定为：字符串解码内容去除首尾空白后以 `{` 或 `[` 开始，并能完整解析为对象或数组。
- 普通字符串、数字字符串、URL、JWT、Base64、布尔值和 null 不自动识别，避免把 `"123"` 误当内嵌结构。
- 多重编码但解码后仍为字符串的情况，首版不自动识别；后续可增加显式“再解码一层”，本轮不猜测编码次数。
- 源文档不合法时先提示修复当前层；首版不允许在不完整父 JSON 上应用修改。
- 属性名中的点、斜杠、引号不能用于字符串拼接寻址；内部路径使用 `(string | number)[]`，展示路径单独转义。

### 3.2 不改变无关内容

不能对整个父文档执行 parse → 修改对象 → stringify 再回写，否则会改变排版、重复键以及大整数精度。

- 按解析树记录的字符串 token 范围，使用 `JSON.stringify(无损压缩后的内层文本)` 生成一个合法 JSON 字符串字面量，仅替换这个 token。
- 父文档其余字符逐字保持不变，包括缩进、换行、字段顺序及数字原文。
- 内层初次排版与新增的格式化逻辑使用基于文本 edit 的格式化方案；压缩通过语法 token 去除字符串外空白，禁止用普通 JS 对象重序列化造成大整数损失。可复用为原有格式化/压缩的后续统一实现，但 V3 至少保证内层处理无损。
- 对重复键不能仅按路径重新查找；打开时同时保存 token 范围、原始 token、父 model URI 及版本。父 model 改变时禁止沿旧偏移回写，提示重新打开，不猜测目标字段。
- 应用前同步检查父 model 的版本和目标 token；应用过程中不插入异步等待。通过 Monaco `executeEdits` 和 undo stop 作为一个撤销操作，支持 Ctrl/Cmd+Z 恢复整个字符串。
- 未修改直接返回保持原始 token；不会仅因查看而将原有 `\\uXXXX` 写法或空白改写。

## 4. 草稿、持久化与冲突

- 根正文与文件属性继续使用现有 IndexedDB 文档记录及 `useJsonWorkspace` 的保存队列；不为内层建立伪文件，不改变正文存储格式。
- 内层编辑使用独立 session/model，未应用前不触发根正文自动保存。
- 为防止刷新丢失内层编辑，增加独立 IndexedDB 草稿 store（需要数据库版本升级），记录根 nodeId、根正文基线、层级栈、每层原始 token/当前文本及更新时间。升级保持既有文档和属性不变。
- 草稿防抖保存，页面隐藏时尽力 flush；不依赖 beforeunload 异步写入完成。未落盘或保存失败时显示状态，并提供下载草稿，离页提示可能丢失的修改。
- 重开文件时发现草稿，提供“恢复 / 丢弃”，不静默覆盖正文。恢复时重新解析目标；根正文与基线不一致则禁止直接应用，仅允许查看、复制或下载草稿。
- 跨标签页变更、文件删除或重新加载导致基线变化时保留草稿并显示冲突，不自动重定位数组索引或同名字段。
- 完成最外层应用并成功保存后清理对应草稿；保存失败继续保留。草稿大小受限，不将其混入普通正文复制或现有工作区备份。
- 首版建议单层文本上限 1 MiB、单会话草稿序列化上限 5 MiB；超限明确提示，不截断或静默丢弃。具体阈值在样例压测后确认。

## 5. 布局、性能与可访问性

- 复用主编辑器区域和现有滚动约束，切换 Monaco model 而不是销毁根 model，保存每层光标、选区和滚动位置，保留根撤销历史。
- 各层 model URI 包含文件 ID、session ID 和层级 ID；退出会话时释放内层 model、监听器及 worker 任务。
- 复用现有结构解析 worker 的版本机制，新增候选扫描任务；仅解析当前层，防抖扫描且丢弃旧版本返回结果。光标移动只查缓存节点，不重复全文解析。
- 解析只处理数据，不使用 eval、不执行字符串或访问其中的 URL；所有操作在本地完成，不调用 R2 或外部服务。
- 候选菜单支持键盘上下选择、Enter 打开、Esc 关闭；焦点返回入口。进入内层聚焦编辑器，返回后恢复父层焦点。
- Esc 优先处理 Monaco 搜索及当前弹层，不直接丢弃内层编辑。窄屏上下文栏支持横向滚动或省略，按钮保持可达，不新增页面级双重滚动。

## 8. 验收用例

- `data/demo1.json` 的 content 可进入、修改、应用；外层 a 不变，content 仍为 string，重新解析后内容正确。
- 多字段及数组字符串可准确选择；包含点、斜杠、引号的 key 和重复键不会误写其他字段。
- 反斜杠路径、引号、换行、制表符、中文和 Unicode 正确往返，不重复解码。
- 大整数、科学计数法、重复字段、内层格式化/压缩不发生数值或字段损失；外层无关字符逐字不变。
- 仅查看返回不产生编辑；应用可一次撤销和重做；无效 JSON 禁止应用但保留草稿。
- 两层以上内嵌 JSON 可逐层编辑应用；任何一层取消不损坏父层。
- 快速切换、父版本变化、跨标签页修改与删除都不会将草稿写到错误文件或旧位置。
- 刷新恢复、保存失败、超限、数据库升级不会损坏原文；未应用草稿状态与根正文保存状态明确区分。
- 现有格式化、搜索替换、复制、面包屑、文件属性、侧栏拖拽、滚动及主题正常。
- 测试与生产构建通过后再按用户要求部署 Cloudflare；设计阶段不发布。

## 9. 已确定的产品选择

本轮已采用以下方案：

1. 使用“进入内层编辑”的单编辑区交互，保持现有布局简洁。
2. 已根据使用反馈确定：应用时统一无损压缩；仅查看后返回仍不修改正文。显式点击“应用到上层”即执行压缩回写，即使未输入修改。
3. 多层编辑与草稿恢复一并交付，支持刷新恢复及文件切换保护。

## 10. 本地实现记录（2026-11-26）

- 新增工具栏内嵌 JSON 图标和 Monaco 右键入口，支持候选列表、路径筛选及键盘选择；解析中入口暂时禁用。
- 单编辑区切换内层 model，支持最多 8 层编辑、逐层/全部应用、放弃/继续编辑确认及根正文撤销。格式化与压缩采用文本处理，保留大整数和重复键。
- IndexedDB 升级为版本 2，新增独立 `embeddedDrafts` store；原文件树、正文和属性记录保留。未应用草稿支持防抖保存、刷新恢复、下载及保存失败重试。
- 内层草稿活跃时阻止跨标签页通知直接替换编辑器；最终回写仍受原文快照及已有 revision 冲突检查约束。
- 新建、切换、删除文件及离开工具通过统一草稿检查；内层确认使用原生模态 dialog，保证不会被已有文件操作对话框遮挡。
- 候选扫描采用独立 `embeddedJson.worker.ts`，与面包屑 worker 隔离，避免协议互相干扰；导航 UI 直接集成到 `JsonFormatter.tsx`，确认框独立为 `EmbeddedJsonDecision.tsx`，未新增方案中暂拟的 `EmbeddedJsonNavigator.tsx`。
- 单层上限 1 MiB、会话草稿上限 5 MiB；超限不截断内存文本，提示下载。普通字符串、重复编码字符串及非严格 JSON 不自动转换。

### 本地使用

1. 访问 `http://127.0.0.1:3000/json`，在文件正文中粘贴 `data/demo1.json`。
2. 将光标移到 content 字段，点击工具栏“内嵌 JSON”图标，或使用右键“编辑内嵌 JSON”；未命中字段时从候选列表选择。
3. 编辑内层内容，点击“应用到上层”将其编码为字符串回写；仅查看后返回不会修改原文。
4. 有未应用修改时，返回/切换文件会询问如何处理；刷新后点击“恢复草稿”继续编辑。

### 回写空白优化

内层格式化仅服务于阅读。显式应用时自动压缩当前层再编码，逐层应用不会新增排版用的转义换行与缩进。已有历史内嵌字符串不会被全局替换；如需清理，进入相应层后从最深层逐层应用。字符串数据自身的空格、换行保持原样。

### 保留转义开关

工具栏新增“保留转义”，默认勾选，显示可编辑的原始 JSON。取消勾选后，按 JSON 字符串 token 解码一层转义，显示独立只读预览；不递归解析内嵌字符串，不修改文件、内层草稿或撤销历史。预览可能包含未转义引号，因此使用纯文本 model 配合基于原始语法节点映射的高亮 decorations，区分属性名、字符串、数字、布尔值和 null，避免引号干扰高亮及无意义的 JSON 错误标记。提示收纳在标题栏，完整说明通过悬停查看，不额外占用编辑区行高。预览模式支持搜索与复制当前展示文本，禁用格式化、压缩和进入内嵌编辑；勾选后返回原编辑器。当前正文或编辑层级变化时退出预览，无效 JSON 提示修复后再预览。开关为当前界面临时状态，不写入持久化偏好。

### 转义视图切换布局稳定性

切换保留转义时始终保留文件名和原文面包屑栏，不增删占位行；标题提示采用固定占位，避免工具栏重排。两个 Monaco 视图统一行号宽度、字号、折叠栏与滚动条尺寸。首次预览沿用原编辑器滚动位置，返回恢复原编辑器视图状态；重复打开同一正文预览时恢复预览滚动位置。预览中文字长度变化造成的自然换行仍按实际内容显示。

### 转义切换消除加载闪烁

去转义预览改为同步创建并复用本地 Monaco 实例，切换仅更新模型与高亮并显示/隐藏容器，不再挂载带 Loading 占位的 React 编辑器。布局阶段恢复预览滚动位置，文件组件卸载时统一释放预览实例和模型。
